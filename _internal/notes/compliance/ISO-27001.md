# ISO/IEC 27001

- **Status:** NOT ANALYZED
- **Universe:** OSM-C-001 (compliance / governance)
- **OSM schema fields today:** optional stack `mappings.iso27001`;
  optional offering `iso27001_controls`

These fields are reference mappings. They are **not** an ISMS, not a
Statement of Applicability, and not a claim that OSM or any adopter
complies with ISO/IEC 27001.

## 1. Framework overview

ISO/IEC 27001 specifies requirements for an information security
management system (ISMS). Annex A lists reference controls
(ISO/IEC 27001:2022).

## 2. Relevant scope for technological services

Later analysis should ask which 27001 themes a **technological
service catalog** can usefully carry (asset-related controls,
operations, cryptography, supplier security, etc.) without OSM
becoming an ISMS tool.

## 3. OSM concepts/attributes relevant to the framework

Present in the current schema (not yet analyzed as a mapping):

| OSM field | Where |
|-----------|--------|
| `mappings.iso27001` | Technology Stack (free text) |
| `iso27001_controls` | Offering attributes (list of control IDs) |
| `last_security_review` | Offering attributes |
| `asset_coverage` | Offering attributes |
| `data_classification` | Service attributes (data handled by the service) |
| `security_classification` | Service attributes (security sensitivity of the service itself; not the same fact as `data_classification`) |
| Service Owner accountabilities | GOVERNANCE.md (documentation) |

## 5. Missing information

represent the whole standard. What OSM should *not* try to hold is a
later decision.
