# ISO/IEC 27701

**Mapped version:** **ISO/IEC 27701:2025** (Edition 2, published
14 October 2025) — the **standalone PIMS** standard. Do **not**
describe current 27701 as merely an ISO 27001/27002 extension from
the 2019 model. 2019 certificates may remain valid under scheme
rules until a declared transition date; that is certification-body
practice, not OSM.

> **Mapping basis (2026-06-11):** ISO lists 27701 as
> [Published, Edition 2, 2025](https://www.iso.org/standard/27701),
> and independent sources confirm the 14 October 2025 release of a
> standalone, independently certifiable PIMS that replaces the 2019
> extension model
> ([DNV release note](https://www.dnv.com/news/2025/iso-iec-27701-standard-update-release/),
> [Wikipedia — ISO/IEC 27701](https://en.wikipedia.org/wiki/ISO/IEC_27701)).
> The full standard text is paywalled; the edition/date and
> standalone-PIMS status are drawn from these public summaries. Source
> wording was rephrased for licensing compliance.

**Status:** **PARTIAL**

OSM is **not** a PIMS and not a claim of ISO/IEC 27701
certification. Existing privacy / processing-role fields are a
**compatibility representation**. OSM does not model all 27701
processing activities, controller/processor responsibilities, legal
bases, or contracts.

## Mapping table

Each top-level ISO/IEC 27701:2025 concept below carries a status from
the index vocabulary (MAPPED / PARTIAL / EXTERNAL / NOT IN SCOPE /
FUTURE / OPTIONAL), so none is silently missing.

| External concept (27701:2025) | OSM target | Grain | Status + kind | Outside OSM |
|-------------------------------|------------|-------|---------------|-------------|
| PIMS / processing activities | — | Organization / activity | **EXTERNAL** — OSM has no processing-activity entity. | Full PIMS |
| Controller / processor / joint-controller (per **activity** in 27701) | `iso27701_pii_role` | Offering posture | **PARTIAL** — compatibility proxy per offering, not per activity. Dual-role SaaS still one enum. | Activity-level roles, contracts |
| PII categories | `iso27701_pii_categories` | Offering posture | **PARTIAL** — locator, not an inventory. | Inventory of processing |
| Retention characterization | `iso27701_retention_days` | Offering posture | **PARTIAL** — characterization, not a legal schedule. | Retention schedules |
| Stack-level 27701 hint | `mappings.iso27701` | Stack | **MAPPED** — free-text, or `not-applicable`. | — |
| High-level privacy class | `privacy_classification` | Service posture | **MAPPED** — canonical OSM class (**OSM-D-003**). | Competing `iso27701_privacy_classification` (forbidden) |

## Precedence (**OSM-D-003**)

1. `privacy_classification` — canonical OSM high-level privacy
   classification. Keep it.
2. `iso27701_pii_role` and related 27701/GDPR fields — framework
   **compatibility** semantics.

Do not create `iso27701_privacy_classification`,
`gdpr_privacy_classification`, or `dora_privacy_classification`.

`iso27701_pii_role` remains because it is a useful mapping field.
It is **not** a complete ISO 27701 PIMS implementation.

## What stays in ISO 27701 (**EXTERNAL**)

- full PIMS objects
- processing activities
- legal bases
- DPO structures
- contractual mechanisms between controller and processor
- data-subject rights operations

Enumerating PII categories is not a legal basis, DPIA, or transfer
assessment.

Exact field definitions are in
