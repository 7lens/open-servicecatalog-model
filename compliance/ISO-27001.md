# ISO/IEC 27001

OSM is **not** an ISMS, a Statement of Applicability, or a claim of
ISO/IEC 27001 certification.

ISO/IEC 27001 specifies requirements for an information security
management system. Annex A lists reference controls. OSM can carry
**catalog-level** control references for a technological service
without becoming an ISMS tool.

## What maps

| OSM field | Where | Role |
|-----------|--------|------|
| `mappings.iso27001` | Technology Stack | Free-text Annex A control references |
| `iso27001_controls` | Offering posture | List of Annex A control IDs |
| `last_security_review` | Offering posture | Security-operations signal |
| `asset_coverage` | Offering posture | Asset-coverage signal |
| `data_classification` | Service posture | Classification of data the service handles |
| `security_classification` | Service posture | Security sensitivity of the service itself — not the same fact as `data_classification` |

Service Owner security accountabilities are described in
[`GOVERNANCE.md`](../GOVERNANCE.md).

## What stays in ISO 27001

- the organization-level ISMS
- risk treatment and Statement of Applicability
- evidence that a listed control is implemented

Listing control IDs is not evidence that controls are implemented.
Example Annex A IDs are illustrative only.

Exact field definitions are in
